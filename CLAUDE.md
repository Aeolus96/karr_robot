# CLAUDE.md

Monorepo for K.A.R.R. (Keystone Autonomous Resource Rover) (independent 4-wheel steering, driven as Ackermann).
Don't call it swerve and don't mention the university. ROS 2 Jazzy, Ubuntu 24.04. Robot computer: Jetson AGX Orin (arm64).
Dev laptops: x86 Windows/Ubuntu, Apple Silicon macOS. Keep everything arch- and OS-agnostic.

- ROS 2 packages live at the repo top level: `karr_description` (generated URDF), `karr_control` (steering kinematics,
  odometry, ros2_control config, teleop; shared by sim and robot), `karr_gazebo` (Gazebo Harmonic: worlds, sensors,
  bridges, sim xacro that includes karr.urdf). Every package has launch files with args so they compose. The repo is cloned into `~/ros2_ws/src/karr_robot`
  on the robot and is mounted at the same path in the dev container.
- `urdf_prep/` (COLCON_IGNORE): raw SolidWorks export + `tools/convert_sw_export.py`. `karr_description/urdf/karr.urdf`,
  `config/footprint.yaml` and `meshes/` are GENERATED by it. Change values in the script's CONFIG section, never in the
  generated files. Then `./dev.sh verify` and `python3 urdf_prep/tools/make_preview_stl.py` (media/karr.stl).
- Robot-model decisions and open items: `urdf_prep/NOTES.md`.
- `media/`: README hero GIF + HD MP4 of a procedural Blender mission (`render_karr.py` CLI/robot, `karr_world.py` set
  pieces, `karr_mission.py` story + shots, `make_gifs.sh`). Read media/README.md first; the look and every decision so far
  are in docs/design/README.md. Full renders run on the lab PC (skill `lab-5090-render`, CUDA): start the job, then
  `Start-ScheduledTask WSLHold` while it runs or WSL shuts down mid-render. Frames are git-ignored.
- Visuals (docs, diagrams, slides, HTML pages): follow `docs/visual-style/notes.md` (Field Manual: IBM Plex, slate +
  one orange accent, sentence-case headings, signal-path diagrams, build-up decks). Identical copy in karr-safety-core;
  change both together. 3D renders/GIFs: `docs/design/README.md`.
- Dev container: `./dev.sh <cmd>` (Linux/macOS/WSL) or `.\dev.ps1 <cmd>` (Windows). Run commands inside with
  `docker compose -f docker/compose.yaml exec ros ws-env bash -c "<cmd>"` (ROS + workspace sourced).
- From PowerShell, avoid inline double-quoted shell pipelines; put multi-step checks in a script.
- Sim sensor topics/frames must match the real drivers (livox_ros_driver2, zed-ros2-wrapper, u-blox). See karr_gazebo/README.md.
- karr_control: cmd_vel -> limits.py (speed/accel/turn-vs-speed) -> kinematics.py (Ackermann, modes front|four_wheel,
  no crab) -> commands. Both modules are ROS-free; tests: `python3 -m pytest karr_control/test` or `./dev.sh test`.
- Follow REP-103/REP-105. Frame and joint reference: `karr_description/README.md`.
- Never run anything that moves hardware or touches the robot network without asking.
